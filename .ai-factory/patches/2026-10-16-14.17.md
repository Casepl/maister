## Causes and corrections

1. **Browser preparation:** the Librarian harness uniquely forced webpack,
   unlike the package, Docker and real-web production builds. It now uses the
   default bundler and pipes server stdout. Build remains inside the original
   180-second readiness gate. Hidden historical stdout prevents identifying
   the PR's exact last build phase. Same-source push/PR timings support cold
   preparation pressure; local results do not reproduce an Intel browser VM.
2. **Journal publication:** the adapter truncated the public JSON file in
   place. Its accepted permission response also preceded selected-journal
   publication and held-callback installation. The adapter now publishes by
   same-directory atomic rename, and all six parent mutations use
   `atomicWriteJson`. The live parent mutation awaits exact selected/held
   state with no pending permission. Read/publication failures throw and log
   structured causal details before the SDK can reduce them to an internal
   error. Missing optional journal state retains its existing meaning.
3. **P4 response window:** the test waited for successor session creation,
   including capability setup, before releasing a checkpoint response with
   an unchanged 30-second client deadline. The PR reached create at about
   30.374 seconds, after the original response had closed. P4 now holds both
   successor capability reservations after protected metadata commits and
   outside database transactions. It audits the original handler's 409,
   unchanged snapshot and zero stale writes there, then releases publication
   and proves successor create/prompt/exactly-once completion. The 10-second
   reservation budget and all original assertions remain.
4. **Death windows:** three boot controls and concurrency D2 used artificial
   60-second terminal delays. The push reached global TERM about 37 seconds
   after D2 killed its issuing web, while that delay was still pending. Use a
   real adapter terminal barrier with exact command/session/kernel identity,
   release only after issuing-web death and the appropriate worker startup,
   and retain all original recovery, exactly-once and cleanup assertions.
5. **Shutdown ownership:** direct HTTP applications could hold claims outside
   the worker slots joined by shutdown. Track their full claim-to-release
   lifetime, stop admission, cancel preparation and join confirmed cleanup
   before database close; retain failure when release cannot be confirmed.

The canonical contracts are `docs/system-analytics/test-infrastructure.md`
and `docs/system-analytics/execution-prompt-lifecycle.md`. The fixture controls
and shutdown ownership change preserve public HTTP/SSE contracts,
PostgreSQL/SQLite schemas, migrations, operator configuration and infrastructure.
No ADR or migration allocation
is needed. Both Node versions, both web shards per Node, serial isolation,
the 60-minute job and original slice formula remain unchanged.
