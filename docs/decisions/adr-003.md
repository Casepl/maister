# ADR-003: ACP as the agent runtime protocol

> Part of the ADR log — hub, index, and editing rules: [`../decisions.md`](../decisions.md).


**Date:** 2026-05-25
**Status:** Accepted
**Context:** MAIster needs to support multiple coding-agent CLIs
(Claude Code, Codex, eventually Cursor / Aider) without a custom
adapter per agent. M0 spike validated that ACP — the vendor-neutral
Agent Client Protocol from `@agentclientprotocol/sdk@0.22.1` — has
adapter binaries for both targets.

**Decision:** Agent processes are launched as ACP adapter binaries:
`claude-agent-acp` (from `@agentclientprotocol/claude-agent-acp@0.37.0`,
wraps `@anthropic-ai/claude-agent-sdk@0.3.146`) and `codex-acp` (from
`@agentclientprotocol/codex-acp@0.0.44`, bundles `@openai/codex@^0.128.0`).
Supervisor spawns one adapter process per active session via
`child_process.spawn`. The wire is ACP `session/update` notifications
over stdio JSONL.

**Consequences:**

- Adding a third executor (Cursor, Aider) is "find or write the ACP
  adapter binary, add an entry to `BINARY_BY_AGENT`" — no protocol
  changes in MAIster.
- Cross-process resume works by spawning a fresh adapter and restoring the
  prior conversation via the ACP `session/resume` protocol call on the stored
  `acp_session_id`. (The M0 spike verified the round-trip with the raw CLI's
  `claude --resume <uuid>`, "ALBATROSS-42"; the ACP **adapter** does not take a
  `--resume` CLI flag — it ignores argv flags — so the supervisor uses the
  `session/resume` call (both bundled adapters advertise
  `sessionCapabilities.resume`). Using `session/new` on resume silently starts
  an empty session; corrected 2026-06-08, see `supervisor/src/acp-client.ts`.)
- Sessions persist as JSONL files at
  `~/.claude/projects/<cwd-encoded>/<uuid>.jsonl`. The agent's own
  session store IS the checkpoint — no separate checkpoint format.
- Cache key does NOT survive process boundary; each respawn costs
  ~$0.28 of cache_creation tokens. Drives [ADR-006](../decisions.md#adr-006-hybrid-hitl-keep-alive--checkpointresume) keep-alive budget.

**Alternatives Considered:**

- **Bespoke shim per agent CLI:** N×N adapter matrix. ACP collapses it to N×1.
- **MCP-only orchestration:** MCP is for tools, not session lifecycle; wrong abstraction layer.

**Amendment (2026-09-09).** Pins bumped to `@agentclientprotocol/sdk@1.4.0`,
`@agentclientprotocol/claude-agent-acp@0.75.1` (wraps
`@anthropic-ai/claude-agent-sdk@0.3.257`) and `@agentclientprotocol/codex-acp@1.10.0`
(bundles `@openai/codex@^0.153.3`). Trigger: the codex binary bundled by
codex-acp 0.0.44 (`@openai/codex@0.128.0`, unsigned) was removed on a macOS
host, so codex sessions died at spawn, and it predates the operator's
configured model. The SDK 1.x wire is still protocol version 1; the supervisor
keeps the (deprecated but supported) `ClientSideConnection` + `ndJsonStream`
client, tolerates `_`-prefixed extension traffic, and pins codex models through
`session/set_config_option` (ADR-076 amendment). Qualification: supervisor
unit/integration/AB, web AB and live new+resume turns through the supervisor
client on both adapters, recorded in the upgrade commit.

**Amendment (2026-10-27).** Pins bumped to `@agentclientprotocol/sdk@2.0.2`,
`@agentclientprotocol/claude-agent-acp@0.95.0` (wraps
`@anthropic-ai/claude-agent-sdk@0.3.309`) and `@agentclientprotocol/codex-acp@2.2.2`
(bundles `@openai/codex@^0.160.1`). SDK 2 removes `ClientSideConnection`,
`AgentSideConnection` and the `Client`/`Agent` interfaces in favour of an app
API. The supervisor now reaches the SDK only through
`supervisor/src/acp-connection.ts`, which keeps the named calls
(`initialize`, `newSession`, `resumeSession`, `setSessionConfigOption`,
`prompt`, `cancel`, `request`) on top of `client().connect(stream)`; test
fixtures serve their agents through `supervisor/test/fixtures/acp-agent-app.mjs`.
Every import uses the `/unstable` entrypoint, which matches what SDK 1.x
exposed by default (the stable one would strip unstable fields such as turn
usage). The wire stays ACP protocol version 1. Qualification: supervisor
unit/integration and the web unit/integration lanes over the mock adapters;
live adapter turns were not re-run.
